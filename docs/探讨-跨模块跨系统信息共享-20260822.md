## 1. 视频检测 → 发言人区分

### 事实
- 现有：`video_processor` 发 `av/video/detect`（person 框，2 fps）；`speaker_diarizer` 按 `av/audio/segment` 出 S1/S2（声纹，跨时间一致但短段不稳、声线接近会混）。两者**没有交叉**。
- 视频侧真正需要的不是"有人"，是"**谁的嘴在动**"= Active Speaker Detection（ASD）。
- 现成轻量模型：[Light-ASD](https://github.com/Junhua-Liao/Light-ASD)（CVPR 2023，MIT）1.0M 参数 / 0.6 GFLOPs，AVA mAP 94.06%；[LR-ASD](https://github.com/Junhua-Liao/LR-ASD)（IJCV 2025）鲁棒版。输入 = 人脸裁剪序列（TalkNet 系：112×112 灰度、25 fps）+ 同步音频 MFCC；输出每张脸逐帧"在说"概率。demo 用 S3FD 做人脸检测（重），3588 上换 yolov8n-face 的 RKNN 版即可。

### 接法（零改旧模块，纯加一个）
```
av/video/detect (person 框)  ─┐
会议室那一路原始帧           ─┼→ 新模块 av_speaker_locator（人脸框 + Light-ASD）
av/audio/segment (final 段音频)─┘        ↓
                              av/audio/visual_speaker {segment_id, face_idx, bbox, prob}
前端：按 segment_id 与声纹 S<n> 合并 —— 声纹答"是谁"，视觉答"在哪/几个人"
```
- 合并规则（前端 20 行）：同一 segment 声纹给 S2、视觉给 face#1 → 建立 S2↔face#1 映射；之后声纹短段置信低时用视觉兜底；两人声线接近时视觉裁决。
- 单路视频设计正好是为这条留的：会议室摄像头一路、正对与会者。

### 量与边界
- POC 2–3 天：① 62 上跑 Light-ASD demo 验 CPU 帧率（预计与 YOLOv8n 同量级，可 NPU 化，纯 conv+GRU）② 换人脸检测器 ③ 接 MQTT ④ 前端合并。
- **前提**：摄像头能看到脸（俯拍、侧脸、背光都不行）。会议室机位定了再立项；先验算力（DECISIONS 铁律）。
- 不做：唇读转写、人脸识别身份（涉隐私，不进产品）。

## 2. 运维检测 → Node-RED 状态与实际同步

### 事实
- 面板（`中控面板` ui-template）按钮 = 发 ASCII 到快捷中控 `192.168.5.20:8932`，**发完即翻转，无回读**，所以面板态 ≠ 设备态（今天加"二楼餐桌空调"时再次确认）。
- 协议层回读**全部存在**（creator_cc 已实测）：
  - 4 台空调：Modbus 功能码 03 读 4 寄存器（开关/模式/风速/温度），只读安全，查询帧已记录（`creator_cc/docs/空调控制-协议记录.md`）。
  - 灯/窗帘继电器 1-5：`192.168.5.21-25:38388`，CR-POWER8-SPM 有查询帧（演示环境总览 §六）。
- 运维遥测已在总线：`creator/telemetry/<deviceId>/<prop>`，含 ecis `temperature`、`online`、交换机端口错包率等，schema 带 header/source/status。

### 分三层做
| 层 | 做什么 | 量 | 收益 |
|---|---|---|---|
| A 在线/离线 | Node-RED 订 `creator/telemetry/+/online`（ping/ecis collector 已发），面板行按 online 灰/亮，离线不给拨 | 半天（面板模板加一个 `online` 字段 + 一个 mqtt-in 节点） | 不再对离线设备"假操作" |
| B 真状态回读 | 新 `state_poller`（放 creator_cc 或 creator_om 都行）每 5–10s 轮询：空调 Modbus 03、继电器查询帧 → 发 `creator/state/<device> {on, temp, …}`；面板只反映 state、不自翻转 | 1–2 天（空调 1 天已有帧，继电器半天抓样本对照） | 面板 = 真相；语音控制有确认依据 |
| C 架构定型 | 命令 → 设备 → 回读 → state → 面板/语音/告警三方共用；HA 接入后同一口径 | 随 B 落地即成 | 与第 4 项合流 |

### 边界
- 查询帧必须只读（功能码 03 / 查询帧），轮询频率 ≤ 每 5s，别让中控忙不过来（DECISIONS：生产机动形态选窗口）。
- 快捷 ECIS 分布式**无**状态接口（协议手册 169 行零命中），不在此列。

## 3. 语音转写文字 → 其它分布式叠加字幕

### 事实
- 文字已在总线：`av/audio/command_punctuated {text, speaker, physical_id, segment_id}`；声纹/话筒发言人已有。
- 输出端三条路：
  1. **湖森 REST `/api/wall/subtitle`**（索引里有，参数未实测）/ hscmd 字幕写指令（PDF 有、样本未抓）——需在 62 抓一次样本。
  2. **快捷 ECIS**：无 OSD，走不通。
  3. **OBS + 浏览器源（Hermes 表 #3/#4 的由头）**：OBS 以任意视频为底层、`/bigscreen` 作浏览器源叠字幕（需要加 `?overlay=1`：透明背景 + 底部居中 + 只显最近 2 行），HDMI 输出进分布式 TX 当一路信号源。**品牌无关、零协议风险、样式全可调**；代价一台跑 OBS 的机器（Mac mini .249 可兼）+ 一路 TX 输入。

### 建议
- 演示环境 P0 上屏那刀里一并做 OBS 路（`/bigscreen` 加 overlay 参数半天；OBS 配置 1 小时）。
- 湖森 `/api/wall/subtitle` 抓样本 1 天，通了就是"真 OSD"（叠在任意画面上，不占输入）。
- 翻译仍不做（算力/客户两条都没到）。

## 4. 246 绿米网关 —— 是否直接通

### 事实（已探测）
- 246 = Debian 12 盒子（OpenSSH 9.2p1），跑 **Home Assistant**（:8123 在线，认证方式 Home Assistant Local），目录备注"已打通传感器/门磁演示"。李楠的接法 = HA 的 Aqara 集成，**不是绿米私有协议**。
- 246 没开 1883；62/5.6 的 broker 上没有 `homeassistant/#` 主题——HA 现在是孤岛。

### 接法（不碰绿米、不碰李楠代码）
1. **HA → 总线**：HA 内置 **MQTT Statestream** 集成，填我们的 broker（62 或 5.6 的 mosquitto），所有实体状态自动发 `homeassistant/<domain>/<entity_id>/state`（门磁 on/off、温湿度、绿米开关…）。Node-RED / creator_om / 视听理解三方零代码即可订。
2. **总线 → HA**（控制）：HA REST `POST /api/services/switch/turn_on`（长效 token）或 HA 的 MQTT 集成开 discovery 让它订我们的命令 topic。语音意图 `av/control` → 一个 Node-RED 节点转 HA 服务调用即可。
3. 前提：246 的 HA 登录（找李楠要管理员或新建账号），broker 若要跨网段给 HA 访问需允许非 127.0.0.1 监听（62 mosquitto 现在绑 127.0.0.1 要核）。

### 量
- 1 小时配置 + 半小时验证（门磁触发 → Node-RED 弹窗/灯动作）。
