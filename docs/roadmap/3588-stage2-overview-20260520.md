## 客户演示"不让认为卡死"评估

**当前痛点**（user 5/20 强调）：
- audio_processor funasr CPU 整段 final → 用户说完话后 dashboard 空白 1-3s 才出转写带标点 = 客户主观"卡死"
- video_processor 工作正常，但视频墙满 4 路时偶有黑框（5/14 诊断为 MJPEG 端口慢）
- LLM 意图判别异步，但偶尔 Mac mini .193 兜底 RTT 高时控制下发体感"延迟"

**最快"不卡死"的修法**（按性价比）：

| # | 方案 | 投入 | 效果 |
|---|---|---|---|
| **U1** | **方案 D 仿 partial UX 兜底**（之前 5/19 评估的）| 1.3d | dashboard 转写卡显示 "…正在听 (X.Xs)" 视觉占位，体感 90% 解决 |
| **U2** | dashboard 加 "处理中" loader 动画到所有等态卡片 | 0.5d | 通用兜底，所有面板"有反馈" |
| U3 | γ 阶段 1 真 partial（依赖 B 阶段 CER 数据）| 2d | 真逐字蹦但 ASR 风险中 |
| U4 | video MJPEG 偶发黑框诊断 + cache 改进 | 1d | 视频墙演示无黑框 |

**推荐顺序**：**U1 + U2 (1.8d) → 客户演示体感立即提升，γ 阶段 1 等 B CER 数据再决定**。
