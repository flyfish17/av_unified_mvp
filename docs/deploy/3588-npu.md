# 3588 NPU 部署 SOP（SenseVoice ASR + RKLLM）

> 把 av_unified_mvp 的 ASR + LLM 漏斗第 2 层都接到 RK3588 NPU 上。
> ASR：端到端 ~400ms（SenseVoice，§ 2-9，2026-05-12 跑通）
> LLM：首 token 198-274ms（Qwen2.5-1.5B INT8，§ 10，2026-05-13 跑通）
> ASR 模型 `AGPL-3.0` daemon 进程隔离；LLM SDK `Apache 2.0` 但模型 page license 未显式。

## 1. 前置 — 必备

- **硬件**：RK3588 板子（实测 Firefly @ `firefly@192.168.5.6`，16GB RAM，OS Ubuntu 22.04，UTC 时区）
- **NPU 设备节点存在**：`/dev/dri/renderD129 → platform-fdab0000.npu-render` ✅
- **3588 已装**：
  - `rknn-toolkit-lite2 >= 2.3.2` (pip user)
  - `librknnrt.so 2.3.0`（系统级，已在）
  - `ollama` + `mosquitto` 自动起（demo 配置）
  - `~/creator_ai_demo/venv/` Python venv（已含 sounddevice / funasr 等）
- **Mac 侧**：能访问 hf-mirror.com（HuggingFace 国内镜像），`huggingface_hub >= 0.x`

3588 无需访问 HuggingFace 主站（不通），但需要内网 SSH 通 Mac。

## 8. 故障排查

| 症状 | 根因 | 修法 |
|---|---|---|
| daemon stdin EOF | happyme531 script 在 inference 内 print 调试 → 污染 JSON line 协议 | daemon 已 redirect stdout 到 /dev/null inference 期间 |
| `ValueError: index can't contain negative values` | fbank 计算在某些静音段出负 index | daemon 已 try/except → 返 `{"error": "..."}`；processor 自动 return 空，不致命 |
| 大量单字 [final]（"我"/"i"/"아"）| happyme531 模型在低音量段幻听 | processor_arm.py 已加 `min_text_chars >= 2` 过滤 |
| `pkill -f 'audio_processor/main.py'` 杀掉 ssh 自己 | pkill -f 的 pattern 会匹配 ssh 远程 bash command 字符串本身 | 用 `pgrep -f "venv/bin/python.*main\.py"` 拿 PID 再 `kill -TERM $PID` |
| log 时间戳跟"现在"差 8 小时 | 3588 系统时钟用 UTC（非中国时区）| 接受现状，跟 `date` 一致即可 |
| daemon ready 但没产生 [final] | 环境静音（mic rms < 0.020 阈值）| 让人说话；或临时调低 silence_threshold 验证 |

### 10.7 性能 baseline（5/13 实测）

| 指标 | NPU (W8A8) | Ollama qwen2.5-coder:1.5b (CPU, Q4_K_M) | 谁赢 |
|---|---|---|---|
| 首 token short | 198 ms | 928 ms | **NPU 4.7×** |
| 首 token long_intent | 274 ms | 1958 ms | **NPU 7.1×** |
| Decode tok/s | 8.9 | 10.5 | CPU 略快 15% |
| 内存峰值 | 1754 MB | ~1180 MB | 接近 |
| 模型加载（一次） | 2.1s | 7.7s warmup | NPU 3.7× 快 |

短响应场景（意图 JSON ~30 token）端到端 NPU ~3.5s vs CPU ~4.1s。NPU 仍胜，且首 token 体感 4-7× 快 → 语音交互"瞬间响应"。

### 10.8 故障排查

| 症状 | 根因 | 修法 |
|---|---|---|
| daemon stdin EOF 立即死 | librkllmrt printf 写 stdout 污染 JSON 协议 | daemon 已 redirect fd 1 → stderr（`_silence_stdout()`），保留原 stdout fd 写 JSON |
| RKLLM 模型加载 OOM | 模型 1.9GB，3588 同时跑 ASR daemon 1.5GB + av_processor 0.4GB → 接近上限 | `free -h` 检查，需要 ≥ 4GB 可用 |
| `cmd` 输出对但 location 错（如 "机房" → Corridor） | NPU 1.5B 偷换地点偏置 | `engine.py` location anti-hallucination 后置过滤已上线，会拒绝；用户需明示地点或在 `system_config.yaml` 设 `system.default_location` |
| 罕见设备词识别失败（"射灯"/"虚光"） | 1.5B 模型能力上限 | 升级 3B 模型（HF 有 `Qwen2.5-3B-Instruct_W8A8_RK3588`，RAM ↑ ~3.5GB），或加 RAG 设备词表预约束 |
