# 3588 NPU 部署 SOP（SenseVoice RKNN）

> 把 av_unified_mvp 的 ASR 路径接到 RK3588 NPU 上，端到端推理 ~400ms，过阈值 #1 大幅。**国产化主推路径**。
> 2026-05-12 首次跑通。`AGPL-3.0` 模型 daemon 进程隔离，仓库不被传染。

## 1. 前置 — 必备

- **硬件**：RK3588 板子（实测 Firefly @ `firefly@192.168.5.6`，16GB RAM，OS Ubuntu 22.04，UTC 时区）
- **NPU 设备节点存在**：`/dev/dri/renderD129 → platform-fdab0000.npu-render` ✅
- **3588 已装**：
  - `rknn-toolkit-lite2 >= 2.3.2` (pip user)
  - `librknnrt.so 2.3.0`（系统级，已在）
  - `ollama` + `mosquitto` 自动起（demo 配置）
  - `~/creator_ai_demo/venv/` Python venv（已含 sounddevice / funasr 等）
- **Mac 侧**：能访问 hf-mirror.com（HuggingFace 国内镜像），`huggingface_hub >= 0.x`

3588 无需访问 HuggingFace 主站（不通），但需要内网 SSH 通 Mac。

## 2. 下载模型（Mac → 3588 中转）

3588 不通 HF / hf-mirror.com，但通 modelscope。当前路径用 Mac 中转 hf-mirror，未来可改 modelscope 镜像。

```bash
# Mac 上
HF_ENDPOINT=https://hf-mirror.com python3 -c "
from huggingface_hub import snapshot_download
snapshot_download('happyme531/SenseVoiceSmall-RKNN2', local_dir='/tmp/SenseVoiceSmall-RKNN2')
"
# 等 ~3min，下 484 MB `sense-voice-encoder.rknn` + 9 个小文件

# 推到 3588
SSHPASS=firefly sshpass -e ssh firefly@192.168.5.6 'mkdir -p ~/SenseVoiceSmall-RKNN2'
SSHPASS=firefly sshpass -e scp /tmp/SenseVoiceSmall-RKNN2/sense-voice-encoder.rknn \
  /tmp/SenseVoiceSmall-RKNN2/sensevoice_rknn.py \
  /tmp/SenseVoiceSmall-RKNN2/fsmnvad-offline.onnx \
  /tmp/SenseVoiceSmall-RKNN2/chn_jpn_yue_eng_ko_spectok.bpe.model \
  /tmp/SenseVoiceSmall-RKNN2/am.mvn \
  /tmp/SenseVoiceSmall-RKNN2/fsmn-am.mvn \
  /tmp/SenseVoiceSmall-RKNN2/fsmn-config.yaml \
  /tmp/SenseVoiceSmall-RKNN2/embedding.npy \
  /tmp/SenseVoiceSmall-RKNN2/output.wav \
  /tmp/SenseVoiceSmall-RKNN2/README.md \
  firefly@192.168.5.6:~/SenseVoiceSmall-RKNN2/
```

## 6. 集成 av_unified_mvp processor_arm.py（NPU 路径切换）

```bash
SSHPASS=firefly sshpass -e ssh firefly@192.168.5.6 \
  'cd ~/av_unified_mvp && nohup env AV_ASR_BACKEND=sense_voice_arm AV_RKNN_BACKEND=1 \
    ~/creator_ai_demo/venv/bin/python modules/audio_processor/main.py \
    > /tmp/asr_arm.log 2>&1 < /dev/null &'
sleep 5
SSHPASS=firefly sshpass -e ssh firefly@192.168.5.6 'tail -15 /tmp/asr_arm.log'
```

预期 log 关键行：
```
... 启用 RKNN backend (3588 NPU 路径, AV_RKNN_BACKEND=1)
... RKNN daemon ready (pid=..., handshake 1.1s)
... ARM 转写已启动
... [final] <文本> (380-420ms, X.Xs 音频, sense_voice_rknn)
```

`raw_mode=sense_voice_rknn` 区别于 CPU 路径的 `sense_voice_offline`，前端可识别。

## 8. 故障排查

| 症状 | 根因 | 修法 |
|---|---|---|
| daemon stdin EOF | happyme531 script 在 inference 内 print 调试 → 污染 JSON line 协议 | daemon 已 redirect stdout 到 /dev/null inference 期间 |
| `ValueError: index can't contain negative values` | fbank 计算在某些静音段出负 index | daemon 已 try/except → 返 `{"error": "..."}`；processor 自动 return 空，不致命 |
| 大量单字 [final]（"我"/"i"/"아"）| happyme531 模型在低音量段幻听 | processor_arm.py 已加 `min_text_chars >= 2` 过滤 |
| `pkill -f 'audio_processor/main.py'` 杀掉 ssh 自己 | pkill -f 的 pattern 会匹配 ssh 远程 bash command 字符串本身 | 用 `pgrep -f "venv/bin/python.*main\.py"` 拿 PID 再 `kill -TERM $PID` |
| log 时间戳跟"现在"差 8 小时 | 3588 系统时钟用 UTC（非中国时区）| 接受现状，跟 `date` 一致即可 |
| daemon ready 但没产生 [final] | 环境静音（mic rms < 0.020 阈值）| 让人说话；或临时调低 silence_threshold 验证 |
