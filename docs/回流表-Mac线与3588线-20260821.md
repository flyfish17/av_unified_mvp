## 三、结论与下一步

1. **回流方向是单向的：Mac → 3588**。Mac 线在 7 月承担了"纪要机软件能力"的开发（声纹、持久化、人名修复、自愈），3588 线承担了"产品机形态"（组播、profile、部署件）。两边没有自动同步机制，靠人记。
2. **纪要相关 3 项已于 8/21 当日全部回流**（人名修复 / 转写留档 / ws 自愈）。加上声纹发言人区分，**纪要软件能力两线对齐**；S6 声纹改名当日也已补齐，纪要相关无差异。
3. **防再次脱节的最小纪律**：每次在任一仓 `git push` 后，把 commit 行贴到对方仓 `DEVELOPMENT_PLAN.md` 末尾"待回流"小节（一行），周更时清。不做 monorepo、不做自动同步——两线形态确实不同，代码级合并不值。
4. 本机 Mac Studio 的 `av_understanding_mac` 今天已 ff 到 `2da2589`，**以后开工先 `git fetch`**。
5. **品牌不用分支**（8/21 晚）：3588 线已把品牌做成 config `brand:`（name/product/logo），62 湖森脸靠 config 保住、刷 HEAD 不再冲掉。三个形态分支（husion-dnc / stable-3588 / demo-mac）建议退役为 tag；Mac 线若有品牌需求同样走 config（低优，现为 CREATOR 默认态无需改）。
